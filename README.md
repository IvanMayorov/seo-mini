# SEO mini

Бесплатный SEO-сервис для сайтов на русском языке с упором на Яндекс. Он проверяет сайт, предлагает улучшения и помогает спроектировать структуру нового проекта.

Сервис сам собирает и считает факты, а выводы делает ваш ИИ-агент, например Claude Code или Codex. Ключи к моделям сервису не нужны, данные лежат у вас в локальной базе SQLite.

*An open-source SEO toolkit for Russian-language sites and Yandex. Python collects verifiable facts, and your own coding agent turns them into recommendations. Documentation is in Russian.*

## Что умеет

| Задача | Как запустить | Что получится |
|---|---|---|
| Проверить сайт | попросите агента: «проверь SEO сайта», скилл `seo-check` | Объяснение проблем с примерами страниц |
| Предложить улучшения | «что улучшить на сайте?», скилл `seo-improve` | `recommendations.md`: приоритеты, трудозатраты, доказательства |
| Спроектировать сайт с нуля | «накидай структуру сайта», скилл `seo-plan` | `structure.md` и `structure.csv`: дерево страниц, запросы, очередь запуска |

Советы агента проверяются: каждая рекомендация ссылается на конкретные строки базы, а карта страниц — на реальные группы запросов. Ссылка на несуществующие данные останавливает сборку отчёта.

## Установка

Нужен Python 3.12 или новее.

```bash
git clone https://github.com/IvanMayorov/seo-mini.git
```
```bash
cd seo-mini
```
```bash
python3 -m venv .venv
```
```bash
.venv/bin/pip install -e .
```

Откройте папку в своём агенте и опишите задачу обычными словами: он найдёт инструкции через `AGENTS.md`. Если хотите работать из другой папки, установите туда скиллы:

```bash
.venv/bin/seo skills-install --agent claude
```

Для Codex укажите `--agent codex`.

## Запуск без агента

Команды `seo` ниже запускаются как `.venv/bin/seo` или после активации окружения.

```bash
seo init https://example.ru/ --type shop --region 225:Россия --competitor competitor.ru
```
```bash
seo audit --max-pages 2000
```
```bash
seo dashboard
```

`seo init` создаёт `seo.toml`, поэтому дальше домен указывать не нужно. Все настройки описаны в [seo.example.toml](seo.example.toml). HTML-отчёт появится в `reports/<сайт>/report.html`. Пример текстового отчёта лежит в [examples](examples/example.com-audit.md).

Новый проект без сайта:

```bash
seo init --new my-project --type shop --competitor rival.ru --marker мебел
```
```bash
seo plan-collect --seed "купить мебель"
```
```bash
seo plan-select --limit 100
```
```bash
seo plan-clusters --top 100
```

Карту страниц составляет агент, а `seo structure` проверяет её и собирает отчёт.

## Что нужно для каждой возможности

| Возможность | Что нужно | Цена |
|---|---|---|
| Технический аудит | Ничего | Бесплатно |
| Запросы конкурентов и черновая структура | Ничего, используется бесплатный API Букварикса | Бесплатно |
| Реальные запросы и страницы своего сайта | Вход в Вебмастер и Search Console | Бесплатно |
| Визиты и конверсии | Вход в Метрику | Бесплатно |
| Живая выдача, группы по топу, оценка шансов | Ключ Yandex Search API | Около 3 ₽ за 100 запросов на регион ночью, примерно 49 ₽ сразу |
| Спрос по региону | Тот же ключ, Вордстат | Около 2 ₽ за 100 запросов |

Цены указаны по настройкам сервиса, их можно изменить в `seo.toml`. Перед большими запусками сверяйтесь с прайсом Yandex Cloud. Как получить ключи, описано в [docs/setup-keys.md](docs/setup-keys.md).

Платные команды показывают стоимость и запускаются с потолком расходов. Пары «запрос + регион» не оплачиваются повторно в течение 6 дней.

## Основные команды

| Команда | Что делает |
|---|---|
| `seo init <адрес>` | Создаёт настройки сайта |
| `seo init --new <название>` | Создаёт настройки проекта без сайта |
| `seo audit` | Обходит сайт и применяет проверки |
| `seo dashboard` | Собирает HTML-отчёт |
| `seo facts --brief` | Отдаёт агенту сжатые факты в JSON |
| `seo facts --section audit` | Отдаёт один раздел целиком |
| `seo page <url>` | Показывает всё об одной странице |
| `seo advice <файл>` | Проверяет рекомендации агента и собирает отчёт |
| `seo plan-collect` | Собирает запросы конкурентов и стартовых фраз |
| `seo plan-select` | Отбирает запросы для проекта |
| `seo plan-clusters` | Группирует запросы и оценивает шансы |
| `seo structure <файл>` | Проверяет карту страниц и собирает отчёт |
| `seo queries-seed` | Создаёт запросы из разделов сайта |
| `seo serp-submit`, `seo serp-fetch` | Собирают выдачу в отложенном режиме |
| `seo serp-sync` | Собирает выдачу сразу, дороже |
| `seo wordstat-collect` | Собирает спрос |
| `seo auth`, `seo search-collect`, `seo metrika-collect` | Подключают данные Вебмастера, Search Console и Метрики |

Подробности есть в `seo <команда> --help`.

Отложенные запросы Яндекс принимает только с 00:00 до 06:00 МСК, а результаты хранит 12 часов. Запускать их удобно ночным скриптом:

```bash
bash scripts/night-serp.sh
```

`scripts/bukvarix-check.py` сравнивает базы Букварикса с вашей живой выдачей и показывает, можно ли им доверять в вашей нише.

## Что важно понимать

- Сервис не обещает позиции и трафик. Рекомендации со статусом «гипотеза» нужно измерять после внедрения.
- `seo advice` и `seo structure` проверяют существование данных и целостность карты, но не логику выводов.
- Букварикс знает только часть запросов, его частотность относится ко всему миру, а базы регионов и Google обновляются редко. Даты можно посмотреть на [странице баз](https://www.bukvarix.com/about_bases.html).
- Оценка шансов — эвристика по составу топ-10. Она не учитывает ссылки и возраст сайтов.
- Обходчик соблюдает `robots.txt` и делает паузы между запросами. Проверяйте сайты, на которые у вас есть право.
- Соблюдайте условия Яндекса, Google и Букварикса при использовании их API.

## Где что лежит

- `data/` — база SQLite и токены входа. Токены хранятся только на вашем компьютере в файле с доступом для владельца.
- `reports/` — отчёты.
- `seo.toml` — настройки вашего проекта.
- `.env` — ключи Yandex Cloud.
- `seo_service/skills/` — инструкции для агентов.

Всё перечисленное, кроме скиллов, не попадает в git.

## Разработка

```bash
.venv/bin/pip install -e '.[dev]'
```
```bash
.venv/bin/python -m pytest -q
```

Логика сервиса не зависит от модели: новые факты добавляются в `seo_service/facts.py`, а правила аудита — в `seo_service/checks.py`.
